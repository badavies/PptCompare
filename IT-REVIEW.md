## 1. Purpose

PptCompare is a Windows desktop application for comparing two versions of a Microsoft PowerPoint presentation.

It is intended to help users identify changes between presentation versions without modifying either source file. Presentations are processed locally on the user’s computer.

The application can identify and display:

- Added, removed, changed and reordered slides.
- Text changes, with additions and removals highlighted in place.
- Text formatting, including font, colour, bold, italic, underline, strike-through, subscript and superscript.
- Tables while retaining their row and column structure.
- Added, removed or changed images and shapes.
- Layout and positional differences.
- A summary of detected changes.

It provides two preview modes:

1. An immediate built-in preview generated from the PowerPoint Open XML document structure.
2. An optional high-fidelity preview generated by an installed desktop copy of Microsoft PowerPoint.

The built-in comparison continues to work if PowerPoint is unavailable or high-fidelity rendering fails.

## 2. Current scope

The current release compares files selected from the local computer or an accessible mapped/network location.

Supported file formats are:

- `.pptx`
- `.pptm`

Legacy binary `.ppt` files are not supported.

Microsoft Graph, SharePoint version-history retrieval and Microsoft Entra authentication are planned extension points but are not currently implemented. The application currently has:

- No cloud connection.
- No database.
- No web server.
- No authentication system.
- No telemetry or analytics.
- No direct network communication.
- No automatic update service.

A separate security review will be required if SharePoint or Microsoft Graph integration is added.

## 4. Supported environment

The application targets Windows 11 and is published separately for:

- Windows x64 computers.
- Windows ARM64 computers, including suitable ARM-based Surface devices.

WPF is Windows-specific, so the application is not intended for macOS, Linux, Android or iOS.

Desktop Microsoft PowerPoint is optional. When high-fidelity previews are required, PowerPoint must be locally installed, licensed and available in the interactive user session.

PptCompare should not be run as a Windows service, scheduled SYSTEM task or server-side process. Microsoft Office applications are designed for an interactive desktop and Microsoft does not support unattended server-side Office automation. [Microsoft Office automation guidance](https://support.microsoft.com/en-us/topic/considerations-for-server-side-automation-of-office-48bcfe93-8a89-47f1-0bce-017433ad79e2)

## 5. Deployment model

Current releases are portable, self-contained .NET applications.

Two release packages are produced:

- `PptCompare-[version]-win-x64.zip`
- `PptCompare-[version]-win-arm64.zip`

The complete contents of the relevant package must be extracted before the application is run. Native WPF DLL files included beside the executable are required and must remain with it.

Because the application is self-contained:

- The destination computer does not need a separately installed .NET 10 runtime.
- The published package contains its own .NET and WPF runtime components.
- Installed .NET updates do not automatically patch the runtime bundled into PptCompare.
- PptCompare must be rebuilt and redeployed when relevant .NET security patches are released.

Microsoft confirms that self-contained applications must be republished to receive newer runtime patches. [Microsoft self-contained runtime servicing guidance](https://learn.microsoft.com/en-us/dotnet/core/deploying/runtime-patch-selection)

.NET 10 is an active Long-Term Support release, currently scheduled to remain supported until November 2028. Applications must remain on a supported patch level. [.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy)

For managed workplace deployment, the recommended method is separate x64 and ARM64 Intune packages with:

- Architecture-specific assignment or requirements.
- Version-based detection rules.
- Installation and removal scripts.
- Authenticode signing and timestamping.
- A documented rollback procedure.

## 6. Application permissions and operating-system interaction

PptCompare is designed to run under a normal user account and should not require administrator privileges.

It requires permission to:

- Read presentations explicitly selected by the user.
- Write settings and logs under `%LocalAppData%\PptCompare`.
- Create and remove temporary files under the user’s temporary directory.
- Read the Windows registration details for Microsoft PowerPoint.
- Start or communicate with desktop PowerPoint when high-fidelity rendering is enabled.

It does not install:

- Windows services.
- Drivers.
- Browser extensions.
- Scheduled tasks.
- System-wide registry settings.
- Listening network ports.

## 7. Presentation and data handling

Presentation files must be treated as untrusted input.

The application applies configurable, bounded limits to reduce excessive memory, storage and processing consumption. Current defaults include:

- Maximum presentation size: 250 MB.
- Maximum slide count: 2,000.
- Maximum embedded-item size: 100 MB.
- Maximum embedded-content relationship references: 100,000.
- Maximum unique related parts: 10,000.
- Maximum cumulative decompressed related content: 500 MB.
- Maximum preview image size: 25 MB per image.
- Maximum combined preview-image size: 100 MB.
- Maximum retained decoded image pixels: 20 million per displayed slide preview.

Additional limits apply to slide elements, table cells, paragraphs and extracted characters.

Before WPF decodes embedded image data, PptCompare allow-lists PNG/JPEG signatures and validates source dimensions, pixel count and aspect ratio. Unsupported embedded formats remain part of content-hash comparison but are represented by a placeholder in the built-in preview; PowerPoint-rendered previews can still display them.

Presentations are:

- Opened read-only.
- Never saved or changed by PptCompare.
- Parsed locally using the Open XML SDK.
- Staged as temporary copies before PowerPoint rendering.

For `.pptm` files, macros are not executed during Open XML comparison. Before a staged copy is opened through PowerPoint automation, the application sets PowerPoint automation security to force-disable macros and subsequently restores the previous setting. This follows the security mechanism documented for programmatically opened presentations. [PowerPoint AutomationSecurity documentation](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.application.automationsecurity)

PowerPoint remains subject to the organisation’s existing Trust Center, Protected View, Defender, Attack Surface Reduction and endpoint security policies.

## 8. Temporary data

High-fidelity rendering creates:

- A temporary copy of the selected presentation.
- Temporary PNG preview images exported by PowerPoint.

The application performs bounded retention and stale-folder cleanup. Cleanup is best-effort because files could remain temporarily following a computer crash, forced termination or storage error.

Normal file deletion is not cryptographic erasure. Organisations processing highly classified presentations should therefore rely on appropriate endpoint controls such as:

- BitLocker device encryption.
- Controlled user profiles.
- Managed temporary-storage policies.
- Appropriate device disposal procedures.

## 9. Existing PowerPoint sessions

The application includes safeguards intended to prevent loss of unsaved PowerPoint work.

It must never:

- Kill `POWERPNT.EXE`.
- Close a presentation it did not open.
- Close an existing PowerPoint session.
- Save or alter the original presentation.

PowerPoint automation is serialized on a dedicated STA thread. PptCompare opens only a staged, read-only copy and attempts to close only that copy.

If a render times out or is cancelled, its serialization lease is retained until the STA worker actually exits. A later request therefore cannot overlap the still-running COM operation.

PowerPoint is asked to exit only when PptCompare has strong evidence that:

- PowerPoint was not already running.
- PptCompare started the automation session.
- Its staged presentation closed successfully.
- No other presentations remain open.

If ownership cannot be established safely, PowerPoint is left running.

These safeguards have automated regression coverage, but IT should still test the application against the organisation’s deployed Microsoft 365 Apps version, security policies and Office update channel.

## 10. Local settings and diagnostics

Per-user settings are stored in:

```text
%LocalAppData%\PptCompare\settings.json
```

The settings file:

- Has a maximum accepted size of 64 KB.
- Is strictly deserialized.
- Rejects unknown or invalid values.
- Is written through a temporary file before replacement.
- Falls back to safe defaults if it is missing or malformed.

Diagnostics are stored under:

```text
%LocalAppData%\PptCompare\Logs
```

Logs:

- Are limited to approximately 1 MB per file.
- Retain a maximum of four archives.
- Do not intentionally record presentation content, presentation names, full paths, usernames or exception messages.
- Record sanitized event names, exception types and HRESULT values.
- Provide optional, user-controlled debug logging subject to the same privacy restrictions.

No logs are transmitted automatically.

## 11. Development assurance currently present

The repository currently includes:

- Nullable-reference-type checking.
- Microsoft .NET analyzers at the latest recommended analysis level.
- Compiler and analyser warnings treated as build errors.
- Code-style validation during builds.
- Deterministic compilation.
- Locked NuGet dependency restoration.
- Qodana static-analysis configuration.
- Unit and regression tests covering:
  - Slide matching and reordering.
  - Text and image comparison.
  - Cancellation.
  - Presentation extension, document type, package structure and input validation.
  - Per-item and cumulative presentation resource budgets.
  - Application settings boundaries, incorrect input types and strict JSON persistence.
  - Raster signature, dimension, pixel and aggregate decode limits.
  - Diagnostic-log privacy.
  - Temporary-file cleanup.
  - PowerPoint ownership and shutdown safety.
  - PowerPoint timeout serialization and queued-render cancellation.
  - Preview retry behaviour.

The repository does not currently contain a committed automated CI/CD workflow. Before wider deployment, it would be advisable to run build, test, static analysis and dependency checks automatically for every pull request and release.

The project has not been represented as independently penetration-tested, externally audited or formally certified.

## 12. Known limitations

IT and users should understand that:

- This is currently an early pilot release.
- The comparison should support human review but should not be treated as forensic proof that two files are equivalent.
- Complex PowerPoint functionality such as animations, transitions, SmartArt, charts, embedded OLE objects, unusual fonts or vendor-specific extensions may not be represented perfectly in the built-in preview.
- High-fidelity preview generation depends on PowerPoint and may be affected by Office licensing, startup state, add-ins, Trust Center settings or endpoint policies.
- Password-protected, encrypted, corrupted or unsupported presentations may be rejected.
- The application has no automatic update mechanism.
- Portable deletion does not automatically remove per-user settings and logs.
- There is currently no formal support SLA.
